# megin-project-knowledge

Read [repository-workflow.md](../megin/references/repository-workflow.md), [workspace-workflow.md](../megin/references/workspace-workflow.md), [new-work-evidence.md](../megin/references/new-work-evidence.md) and [language-policy.md](../megin/references/language-policy.md).

Inspect established project documentation before proposing a format/location. Keep durable Repo knowledge in each selected Repo and work-specific progress in the selected root's Work ID. Prefer existing architecture/operations/decision records; preserve provenance, version, confidence and unresolved questions.

Plan source-backed knowledge changes with approved paths/checks, apply them with implementation and review/verify them as product files. Group-wide work records may link approved cross-Repo facts. Reconcile/promote knowledge only after human acceptance. Do not expand scope to unrelated Repos or documentation.
