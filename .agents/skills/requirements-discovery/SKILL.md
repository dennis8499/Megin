# 需求探索

以證據先行的訪談，把仍待釐清的構想收斂成可驗收、可追溯，且足以進入技術規劃的需求分析。

`frontier` 是目前前置決策已解決、可以請使用者決定的未知節點。每輪只處理 frontier 中價值最高的一項，直到品質門檻通過。

## 探索邊界

- 需求分析描述 `為什麼`、`要什麼`、`由誰使用`、`何時成立` 與 `如何驗收`；架構、技術選型、內部 API、程式結構、實作步驟與工作拆分交由後續技術規劃。
- 探索回合只進行事實查證、需求提問與文件草擬；外部已強制的技術限制可記入需求。
- 使用者對探索問題的回答只確認該項決策。寫檔、實作與其他變更各自需要對應授權。
- 使用使用者的主要語言提問與成文；保留必要的領域原文，所有識別碼維持 ASCII。
- 每份文件只涵蓋一個可獨立規劃、驗收或發布的成果。

## 探索流程

### 1. 先查明可取得的事實

在第一個問題前，檢查可用的專案脈絡，包括適用的 `AGENTS.md`、治理文件、README、既有規格、領域詞彙、資料模型、介面、程式碼與近期變更。必要且獲准時，再查外部的一手資料。

只把需要人做決定、確認優先順序或提供無法存取資訊的事項放入 frontier。必要事實無法取得時，先簡述已查過的位置，再將該缺口作為唯一問題。

**完成條件：** 所有目前可存取、且可能改變範圍、行為、風險或驗收的事實都已有來源；剩餘問題都需要人類決策或目前無法取得的資訊。

### 2. 建立工作中的覆蓋圖與決策樹

維護內部覆蓋圖，將每個項目標成 `已確認`、`未知`、`矛盾` 或 `不適用`。只向使用者摘要已知內容與目前缺口。

逐項判斷下列覆蓋面是否適用：

1. 問題、價值、為何現在做、預期成果
2. 利害關係人、使用者、系統角色與決策權
3. 範圍、非目標、優先順序與發布邊界
4. 現況流程、目標流程、主要與替代旅程
5. 功能行為、業務規則、權限與狀態轉換
6. 領域詞彙、資料、實體、所有權與生命週期
7. 外部整合、上下游、契約與失敗處理
8. 使用體驗、無障礙、在地化與人工介入
9. 效能、可用性、安全、隱私、稽核等品質屬性
10. 邊界條件、錯誤、重試、復原與降級
11. 限制、依賴、移轉、相容性與過渡需求
12. 風險、法規、政策與必要的人工作業審查
13. 驗收條件、成功指標、來源與追溯關係

只有事實支持時才標記 `不適用`。把所有會影響範圍、行為、風險或驗收的適用未知事項放進決策樹；未經確認的預設值仍是未知。純 HOW 決策標記為後續技術規劃，不進入 frontier。

若任一覆蓋面涉及法規、合約、安全、隱私、醫療、金融、兒少、身分或其他高風險領域，在提出下一題前完整閱讀[品質契約](references/quality-contract.md)，並把其中的高風險門檻加入覆蓋圖。

**完成條件：** 13 個覆蓋面都有狀態，所有適用未知事項都有決策前置關係；frontier 只包含前置決策已解決的節點，或在沒有這類節點時為空。

### 3. 每輪只問一個最高價值問題

依 `影響程度 × 不確定性 × 不可逆性` 選擇 frontier 中價值最高的節點；同分時依序處理：

1. 範圍與業務成果
2. 法規、安全與隱私
3. 驗收與可測試性
4. 角色、業務規則與資料
5. 使用體驗
6. 營運限制與外部技術限制

每個回合只請使用者決定這一個節點。問題必須：

- 可單獨理解，先用一至兩句交代已知脈絡與決定的影響。
- 在適合時提供二至四個互斥且有實質差異的選項，簡述各自後果，並允許簡短自訂答案。
- 只有在專案證據、一手資料或清楚的領域慣例支持時才推薦選項；若沒有可靠依據，明說不偏好任何選項。
- 讓使用者能只回覆選項標籤或一句話。
- 以單一決策請求結束，不附帶另一項詢問。

**完成條件：** 本回合只要求一項使用者決策，而且該決策是 frontier 中目前價值最高的節點。

### 4. 收斂並重算 frontier

- 將答案、決策者或證據來源記入覆蓋圖。
- 答案含糊、互相衝突或引入高影響歧義時，讓同一決策留在 frontier，下一輪只釐清該決策。
- 同一詞彙有多種含義時，先將定義作為決策。
- 新需求跨出成果邊界時，先確認納入、延後或另立文件。
- 輸入含多個可獨立規劃、驗收或發布的子系統時，提出最小拆分、依賴與建議順序，再把「先探索哪一份」作為唯一問題。

更新覆蓋圖與決策樹，再回到步驟 3。題數由 frontier 決定。

**完成條件：** 本輪答案已有來源，所有衍生未知與矛盾都已入圖，而且 frontier 已依最新前置關係重算。

### 5. 通過品質門檻

只有 frontier 與其後續未知節點都為空、且沒有矛盾或未定義關鍵詞時，才完整閱讀或重新閱讀[品質契約](references/quality-contract.md)，逐項執行二元檢查。

- 任一檢查失敗：把失敗項目轉回覆蓋圖中的 `未知` 或 `矛盾`，回到一次一題的 frontier 迴圈。
- 所有適用檢查通過：探索完成，進入交付分支。

**完成條件：** 品質契約的每個適用項目都有可核對的通過證據；任何未通過項目都會讓探索繼續或進入阻塞狀態。

## 中斷與交付

當使用者要求提前停止、索取目前成果、要求開始實作，或步驟 5 已通過時，回應前完整閱讀[交付協定](references/delivery-protocol.md)，只執行其中符合目前狀態的分支。交付協定決定文件狀態、模板載入、建議路徑、寫檔確認與技術規劃交接。
